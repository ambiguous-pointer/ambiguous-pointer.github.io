VitePress Runtime API

把博客变成可交互知识工作台

这个页面不是普通文档页。它把 Markdown 内容、运行时 API、客户端组件和程序化导航组合在一起， 展示 VitePress 可以承载的更大交互边界。

API 能把站点扩展到什么程度 ​

VitePress 的运行时 API 不是大型应用框架的替代品，但它足够把一个普通博客升级成“知识工作台”。

它最适合承担这些能力：

API可以做的事情
useData()读取站点配置、主题配置、当前页面 frontmatter、标题、暗色模式
useRoute()感知当前路径，用于页面状态、阅读轨迹、上下文面板
useRouter()在 Vue 组件里做程序化跳转、向导流程、项目卡片导航
withBase()处理 public 静态资源路径，避免部署到子路径后资源失效
<Content />自定义布局中继续渲染 Markdown 正文
<ClientOnly />包住 canvas、WebGL、localStorage、编辑器等浏览器专用组件
$frontmatter在 Markdown 中快速读取页面元数据

适合你这个站点的方向 ​

  1. 全屏 Vue 工作台：已经用于 /workspace。
  2. 交互式简历和项目详情：已经用于 /about/。
  3. Runtime API 实验室：当前页面展示 Markdown 与 Vue 面板并排。
  4. 后续可以做文章知识图谱、项目关系图、标签分析、阅读路线推荐。

Markdown 仍然有价值 ​

即使做交互页面，也不必完全抛弃 Markdown。比较好的组合是：

  1. Markdown 写说明、背景、结论。
  2. Vue 负责交互、筛选、可视化和跳转。
  3. 自定义 Layout 决定页面是不是文档风格、实验室风格或全屏应用风格。

这个页面就是这种模式：左侧是 Markdown 内容，右侧是运行时 API 面板和客户端 canvas。
